# 安全、隐私与运维设计

状态：Draft

## 1. 身份与授权

- 认证接入由统一身份层负责；应用从可信认证上下文获取 user ID。
- 项目角色首期为 owner/editor/viewer。
- owner 可管理项目和成员；editor 可修改作品和分析结果；viewer 只读。
- 每个 API 都执行对象级授权；前端隐藏按钮不构成安全控制。
- 所有列表查询必须在 SQL 层限定用户可访问的项目范围，防止 IDOR。
- Worker 使用最小权限的服务身份，不接受客户端传入任意 project/work 作为可信授权依据。

## 2. 文件导入安全

- 白名单校验媒体类型和扩展名；文件名仅作为展示信息，不作为路径。
- 配置最大文件大小、单项目存储配额、单用户并发上传数和解析超时。
- 对压缩包/EPUB 等格式防范路径穿越、压缩炸弹和异常嵌套；首期 TXT 优先。
- 上传文件与规范化文本分开存储，使用不可预测对象 key。
- 下载原文件需再次鉴权；对象存储默认私有。
- 原始文件哈希用于完整性和重复检测，不作为权限凭证。

## 3. 文本与模型数据保护

- 默认不在应用日志中记录完整正文、完整提示词或模型原始上下文。
- 日志只记录 run ID、step key、资源 ID、模型 ID、耗时、token 用量和错误码。
- 模型网关应支持配置可用的模型提供方、数据发送范围和禁止外发的工作区策略。
- 私有部署场景可以将模型请求路由到内网模型；敏感作品不得在未授权时发往外部 API。
- 数据导出、永久删除和备份清理应有明确流程。

## 4. 版权与使用边界

- 上传者必须拥有或获得处理文本的适当授权。
- 系统用于个人研究/阅读的作品与原创作品需要区分来源和权利状态。
- 不默认提供整本受版权保护作品的公开分享或全文再分发。
- 证据展示遵循最小必要引用原则；引用长度和导出策略可配置。
- 用户生成正文与参考作品的关系、来源和许可需要在产品规则中明确。
- 本文为产品技术控制建议，不替代具体司法辖区的法律审查。

## 5. 密钥和配置

- 数据库密码、对象存储密钥、模型 API key 使用环境注入或专用密钥管理系统。
- 不把生产密钥提交到 Git、前端 bundle 或日志。
- 配置区分 local/test/staging/production；敏感配置不允许通过普通 API 回显。
- 提示词模板可以版本化，但不得将密钥硬编码进模板。

## 6. 任务与成本保护

- 设置每用户/每项目并发 run 上限。
- 设置每个 run 的章节数、最大 token、最大重试、最大执行时间和成本预算。
- 对连续失败、模型限流和服务不可用进行退避；避免重试风暴。
- 用户取消任务后不再启动新阶段。
- 提供管理员级暂停队列和限制模型路由的操作。

## 7. 备份与恢复

- PostgreSQL 定期备份并验证恢复。
- 对象存储启用版本或不可变备份策略（按部署能力）。
- 数据库恢复后验证对象 key 可访问性、source hash、artifact/run 关系。
- 迁移回滚仅适用于明确可逆的 schema 变更；数据变换迁移必须提供恢复策略。
- 生产迁移前备份并在 staging 执行相同脚本。

## 8. 可观测性

指标：
- API 请求量、错误率、P95 延迟。
- 上传和解析成功率。
- analysis run/step 状态分布、队列年龄、lease 过期数。
- 模型请求成功率、延迟、token、费用和 schema 验证失败数。
- evidence verification 通过率和 unsupported claim 比例。
- PostgreSQL 连接池、慢查询、存储使用量。

告警：
- 任务队列持续积压。
- worker heartbeat 停滞。
- 模型连续失败或成本异常。
- 对象存储/数据库错误。
- 证据验证率显著下降。
