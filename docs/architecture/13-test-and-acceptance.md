# 测试策略与验收标准

状态：Draft

## 1. 测试分层

### 单元测试
覆盖领域规则、状态转换、offset 计算、实体消歧决策、故事线排序、输入 hash、schema 验证和重试策略。

### 数据库集成测试
使用真实 PostgreSQL 验证 migration up/down、复合外键、唯一约束、事务回滚、并发 revision、跨 work 关联拒绝和删除规则。

### API 合约测试
验证请求校验、错误 envelope、分页、权限、幂等键、并发冲突和 DTO 兼容性。

### Worker 故障测试
模拟进程崩溃、重复消息、模型超时、限流、部分结果成功、lease 过期、取消和重试。

### 前端交互测试
覆盖导入向导、章节修正、证据跳转、审核操作、大纲节点移动、版本冲突、任务失败和权限限制。

### AI 质量回归
使用固定小说样本、人工标注的章节/人物/事件/证据和预期关系，按模型、提示词和 schema 版本进行回归比较。

## 2. 数据正确性用例

- 同一 source version 的 split version 不得引用另一 source version。
- 同一 work 的 relation 不得连接其他 work 的实体或事件。
- 同一 outline set 的节点不得把另一 outline set 的节点作为 parent。
- evidence anchor 不得跨 split version。
- 引用区间越界、quote mismatch、hash mismatch 必须失败或标记 invalid。
- 人物合并不得产生自环、循环 merge 或跨 work 引用。
- 同一 Idempotency-Key 和相同输入返回同一 run；输入不同则冲突。
- 重试不重复插入 artifacts、claims、events 或 aliases。
- outbox 在业务事务回滚时不产生；业务事务提交后进程崩溃仍可投递；重复投递不重复产生外部副作用。
- 新 source/split version 不得把旧 artifact 显示为当前有效结果。

## 3. MVP 验收

M1 导入：
- 能上传合法 TXT，计算 SHA-256 并存储。
- 能创建 source version、split draft 和章节预览。
- 用户能修正边界并确认版本。
- 失败可重试且错误可诊断。

M2 分析：
- 能异步分析选定章节。
- 输出通过 schema 校验。
- 每条关键结论可打开原文证据。
- worker 重启后能恢复未完成步骤。
- 用户可接受、编辑或拒绝分析结果。

M3 跨章节：
- 能将同一人物的候选提及归并到同一实体，同时保留别名。
- 歧义人物不被自动合并。
- 主线/支线节点可按叙事顺序浏览。
- 大纲树支持增加、移动和重排。
- 所有结构都能跳回来源章节。

## 4. 测试语料

维护可再分发或获得授权的测试语料。每个样本记录来源、许可、语言、章节规则和人工标注版本。不要把未经授权的整本畅销小说作为公开 CI fixture。

测试集应覆盖中文标点、全角空格、Unicode、繁简文本、章节名相似、章节内分隔符、无标题章节和超长章节。

## 5. 发布门禁

任何 SQL 或领域模型 PR 必须：
- 更新相关设计文档和数据字典。
- 通过迁移 up/down 集成测试。
- 通过领域不变量测试。
- 对破坏性变更提供迁移/回滚说明。

任何提示词/模型 PR 必须：
- 指定 prompt/template 版本。
- 运行 schema 和 evidence 校验。
- 报告固定样本集指标变化。
- 说明延迟、token 成本和质量权衡。

任何页面 PR 必须：
- 覆盖加载、空状态、失败、无权限和冲突状态。
- 不在前端单独假定服务端操作成功。
