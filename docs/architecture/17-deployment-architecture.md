# 部署架构与环境设计

状态：Draft

## 1. 环境

- local：开发者本地，使用独立数据库和对象存储 bucket。
- test：自动化测试，使用临时数据库/测试对象存储。
- staging：尽可能复刻生产拓扑，验证迁移、任务恢复和模型路由。
- production：正式用户数据和持久化存储。

禁止开发/测试环境复用生产密钥或将生产正文复制到未授权测试环境。

## 2. 初期部署单元

- web：Next.js 静态/服务端应用。
- api：Go HTTP API。
- worker：Go 异步执行进程。
- preprocessor：文本解析与规范化接口。
- postgres：事务数据库。
- object storage：原始文件和规范化全文。
- model endpoints：内网模型或获批的外部模型服务。

API 与 worker 可共用一个镜像但使用不同 command。worker 数量按并发和模型限制配置，不能无限扩容。

## 3. 配置类别

非敏感配置：
- 环境名、监听地址、日志级别、请求超时、并发限制、最大上传大小。
- 数据库连接池上限、任务 lease 时长、重试策略。
- 模型路由、token 预算、任务配额。

敏感配置：
- PostgreSQL 密码。
- 对象存储 access key/secret。
- 模型 API key。
- 外部身份认证客户端密钥。

敏感配置通过环境注入或密钥管理系统提供，不写入配置仓库。

## 4. 健康检查

- liveness：进程是否活着，不应依赖模型服务或数据库瞬时可用性。
- readiness：数据库连接和必要配置是否就绪。
- worker health：心跳、任务 lease、最近成功任务时间。
- preprocessor health：版本信息、解析器可用性和依赖状态。

健康接口不得暴露凭证、完整配置或用户数据。

## 5. 发布顺序

1. 备份数据库和对象存储关键元数据。
2. 在 staging 执行 migration。
3. 运行迁移后检查和关键集成测试。
4. 发布兼容的 API/worker。
5. 观察错误率、队列、模型成本和证据验证率。
6. 若需回滚应用，确认 schema 向后兼容；数据库回滚单独评估，不默认自动执行。
7. 记录发布版本、迁移版本和回滚结果。

## 6. 资源规划原则

首期资源按实际并发和模型部署情况测量，不提前给出虚假的固定规格。主要资源瓶颈：
- PostgreSQL：全文章节读取、关系查询和任务状态写入。
- 对象存储：原始文件、规范化全文和导出。
- Worker：模型并发、CPU 文本处理和重试。
- 模型端点：上下文窗口、吞吐、并发限制和成本。

需要压测的场景包括：多本长篇同时导入、章节批量分析、任务失败重试、多个用户同时浏览关系图和大纲树。
