# 原创小说设计工作流

状态：Draft · 详细设计

## 1. 设计目标

创作工作台不是一个“输入题材，生成几十万字”的黑箱。它应当帮助作者把模糊创意逐渐变成可讨论、可验证、可持续扩展的设计，并保留作者的控制权。

设计对象分为：
- **创作意图**：作者希望探索什么、让读者体验什么。
- **计划模型**：计划人物、事件、故事线、世界规则和大纲。
- **已确认 Canon**：作者明确认可的设定和故事事实。
- **正文版本**：实际写出的章节与修订历史。
- **一致性发现**：计划、Canon 和正文之间的冲突/缺口。

计划事件不等于已发生事件；AI 草稿不自动成为 Canon；用户修改正文不应静默覆盖已确认设定。

## 2. 设计方式：允许不同创作范式

创建作品时允许选择：
- Top-down：先故事核心，再人物/世界、事件骨架、故事线和章节。
- Character-first：先建立人物目标、矛盾和关系，再让冲突推动情节。
- Discovery/pantsing：从人物、场景或局部冲突开始，逐步探索；系统只记录和诊断，不强迫预先写完整大纲。
- Serial-first：针对长篇连载，先建立主线引擎、阶段目标、卷/弧和开放线索，再逐章推进。
- Custom：用户自行组合。

这些模式是工作流偏好，不是不同的数据模型；任何阶段都可以回退、分支、比较和合并方案。

## 3. 阶段一：创作简报与故事承诺

收集或逐步追问：
- 类型、读者、篇幅/连载形式、基调和视角偏好。
- 核心题材与创作动机。
- 想探索的价值冲突/主题问题。
- 读者主要期待：悬疑、成长、权力博弈、情感、冒险、历史沉浸、社会观察等。
- 约束：时代、地点、规则、史实、版权边界、禁区。
- 结局方向：确定结局、多个候选或暂不决定。

产物：CreativeBrief v1。缺项允许保留为开放问题；系统不能用默认答案悄悄填满。

## 4. 阶段二：故事核心

逐步产出多个候选：
- premise：核心设想。
- logline：主角 + 目标 + 核心阻碍 + stakes。
- central dramatic question：贯穿全书的核心问题。
- controlling idea/theme hypothesis：故事可能表达的价值判断，允许存在反命题。
- story promise：读者选择这类故事后合理期待看到什么。
- ending candidates：结局状态、关键选择和代价。

系统应通过问题帮助作者发现缺口：
- 为什么必须是这个主角？
- 为什么现在发生？
- 主角如果不行动会失去什么？
- 反对力量为何不直接获胜？
- 主角的选择如何让问题变得更难？
- 结局是否由前面的选择和代价共同造成？

产物是可比较的 StoryConcept，不自动冻结为唯一方案。

## 5. 阶段三：人物引擎

人物设计不止是一张外貌/性格表。每个核心人物应包含：
- 外部目标、内在需求（可选）、价值观/信念。
- 当前策略和能力、资源、限制。
- 恐惧、盲点、秘密、矛盾和底线。
- 关键关系：利益、依赖、权力、债务、情感、竞争、忠诚。
- 在不同阶段的知识、信念、关系、地位和资源变化。
- 关键选择及代价。

对手不应只是“阻碍主角的人”。其目标、资源、合理性和行动策略需要独立成立；对手的行动应改变主角的可选方案。

人物弧以状态变化和选择来表达，不以“胆小→勇敢”等标签代替。人物可以拒绝成长、堕落、重复失败或保持稳定，只要这种选择具有叙事意义。

## 6. 阶段四：世界、制度与研究

适用于奇幻、科幻、历史、现实题材：
- 规则与边界：能力、资源、技术、法律、制度、地理、经济、组织。
- 规则的代价和限制，避免设定随剧情需要随意变化。
- 历史/现实题材区分：已证实史实、来源解释、学术争议、合理推断、虚构补白。
- 每条重要规则说明它会允许什么、阻止什么、由谁维护、违背后有什么后果。
- 设定应进入人物选择和事件因果，而不是只存在于百科条目中。

## 7. 阶段五：因果骨架与结局反推

作者可以从开端向前推演，也可以从结局向前反推。

对每个关键事件回答：
1. 触发条件是什么？
2. 谁做了决定/行动，为什么是这个人？
3. 还有哪些可选行动，为什么没选？
4. 行动带来什么即时结果与延迟后果？
5. 哪个角色/制度对此作出反应？
6. 这个结果如何改变下一阶段的条件？
7. 删除这个事件，后续哪些事件将不再成立？

如果事件删除后对主线毫无影响，系统只能提示“可能非必要/可能承担人物或主题功能”，不能直接判定无用。因果链也允许偶然、误判、意外和反高潮，但要区分“作者刻意安排的偶然”与“为推进剧情的方便巧合”。

## 8. 阶段六：故事线设计

每条故事线需定义：
- 线的核心问题/目标。
- 关键人物和反对力量。
- 初始状态与结束状态。
- 阶段性转折和代价。
- 开放线索/承诺/秘密。
- 与其他线的交汇点。
- 主题或人物弧功能。
- 预期回收和允许未解的部分。

主线/支线不是按篇幅大小分类，而是按作品的核心问题、因果作用、人物变化和收束作用判断。多个故事线可以共享事件，但应说明各自为何需要该事件。

## 9. 阶段七：宏观结构模板

系统支持可选模板，不强制统一：
- 自由结构。
- 三幕/五幕等阶段模型。
- 英雄旅程/成长弧。
- 悬疑/推理线索与揭示结构。
- 章回体/连载：卷、故事弧、章节单元、阶段高潮和章末悬念。
- 多视角/群像/家族史。
- 用户自定义。

模板是一个诊断镜头：显示预期节点、当前覆盖、缺口和不适配项。用户可以明确标记“有意偏离”；偏离模板不应被系统判为错误。

## 10. 阶段八：大纲逐层细化

层级：作品 → 卷/部 → 故事弧 → 章节 → 场景 → beat。任何层级可以缺失或自定义。

### 章节设计卡
- 本章视角/焦点人物（可空）。
- 本章目标或要解决的问题。
- 冲突/阻碍。
- 关键行动、选择或信息揭示。
- 结果与状态变化。
- 推进的故事线。
- 建立/强化/兑现/有意延迟的线索。
- 读者应知道什么、角色知道什么。
- 结尾状态和下一章承接。
- 相关 Canon、前置事件和依赖项。

### 场景设计卡
- 场景目的。
- 起始状态。
- 参与者各自的目标。
- 阻碍和策略变化。
- 关键选择/转折。
- 结束状态及代价。
- 视角、时间、地点、信息边界。
- 需回收或新增的线索。

允许纯氛围、过渡、回忆或反思场景；系统检查的是“为何放在这里、贡献是什么”，不是所有场景都必须套入相同公式。

## 11. 阶段九：写作、修订与 Canon

生成章节时，仅组装与当前场景相关的上下文：
- 当前章节/场景细纲。
- 必要人物状态、关系和知识状态。
- 已确认世界规则和 Canon。
- 前文摘要、相关原文/正文片段。
- 本章关联的事件、伏笔和故事线。
- 风格/视角/篇幅约束。

生成结果先进入 draft。作者可以编辑、接受、拒绝或分支。接受后的正文产生新 manuscript revision；Canon 变更需要明确操作和原因。

## 12. 一致性与结构诊断

按问题类型产生可解释的 finding：
- 因果缺口：事件缺少必要前提。
- 动机缺口：行动与角色目标/信念冲突，且无文本解释。
- 时间线冲突：日期、年龄、路程或事件顺序矛盾。
- 知识越界：角色使用了尚未获得的信息。
- 规则冲突：世界设定被违反。
- 人物关系冲突：关系/身份/承诺前后不一致。
- 伏笔风险：长期未提及、回收缺少铺垫、回收与原线索不匹配。
- 故事线失联：建立的冲突长期无变化且未说明其功能。
- 节奏风险：事件密度、信息揭示或冲突强度长时间重复。
- 结构模板缺口：可选模板中的关键功能缺失。

每条 finding 包含 severity、evidence/related nodes、reasoning、可能影响范围和修复选项。系统不直接改写正文；作者选择方案后再生成新 revision。

## 13. 变更影响分析

改变 premise、人物目标、关键事件、世界规则或结局时：
1. 查询依赖该对象的事件、故事线、章节和 Canon。
2. 显示直接影响与下游影响。
3. 提出需要重新评审的节点。
4. 用户决定接受修改、保留旧方案或创建分支。
5. 仅重算受影响的检查，不无差别重写全书。

## 14. 创作质量门禁

在进入下一层之前，显示：
- 当前层级已确认/未确认决策。
- 未解决的关键问题。
- 因果依赖缺口。
- 角色动机冲突。
- 未安排回收的线索。
- 与用户目标/类型承诺的偏差。
- 可能存在的模板不适配。

门禁默认是建议，不应阻止作者有意采用开放式、实验性或非传统结构。

## 15. 首期交付建议

首期应先做“设计工作台”而不是整本自动生成：
1. 创作简报和多个故事核心候选。
2. 人物与关系设计。
3. 事件因果骨架。
4. 主线/支线与线索账本。
5. 多层大纲。
6. 设计冲突检查和变更影响分析。

之后再接入章节正文生成和更细的风格控制。
