# ASK 现代长篇网文拆解方法论 V1.0

状态：研究设计稿（Draft）｜首次实验样本：《父可敌国》第一卷《大本堂中》｜目标：从证据化拆书形成可复用的原创网文设计能力

## 0. 方法论一句话

先固定文本和读者所知的截止章，再逐章提取“真实发生/角色声称/角色推测/叙述者说明”，归并成事件、人物状态和知识图；跨章追踪目标、因果、承诺、线索与回收，跨卷解释结构和作者技法，最后把可迁移的机制转换成原创设计检查问题。任何没有原文证据的因果、伏笔、作者意图和“爽点”都只是候选解释。

研究底座：叙事学区分事件在故事世界中的发生顺序和文本的呈现顺序；2024 NAACL 的事件因果研究指出显式因果关系有助于计算故事理解；2025 ACL LongStoryEval 比较了聚合、增量更新和摘要式长篇评价。ASK 不照搬某一种模型，而通过真实网文人工验证抽取效果。

## 1. 实验输入与边界

本轮以用户上传的 EPUB 为依据。《父可敌国》第一卷《大本堂中》在该文件的 OPF spine 里从第 1 章《楚王殿下》到第 73 章《好男儿志在四方》，第 74 章属于第二卷《中都风云》。

一次性解析得到：
- 73 个正文章节，spine 零基 index 为 4–76。
- 段落连接后的正文字符总数为 169,732（Unicode 码点）；中位单章 2,282 字符。
- 这不是版权方官方字数；暂不把预处理文本发布到 Git 仓库。
- 本轮对所有 73 章**确认了目录/正文章界并生成了结构元数据**，对部分关键章节做了阅读抽样与证据定位；尚未人工精读和验收全部 73 章的剧情标注。

每次分析固定以下合同：
- work_id、source_document_hash、source_version、split_version、normalizer_version。
- volume范围、chapter_start、chapter_cutoff、reader_mode（截止章或全书）。
- analysis_profile（结构/因果/人物/线索/文风等）与预算。
- output_schema_version、prompt_version、model route、input_manifest hash。
- 未完结/完结 status 必须与来源元数据区分，缺失时填 unknown。

强约束：数据库里有第 500 章不意味着第 100 章视图可以检索它；模型上下文、搜索、缓存、API、导出和结果合成全链路执行 cutoff。

## 2. 核心理念：两遍阅读、四层建模、三次校验

### 第一遍：事实性解剖（不解释作者目的）
仅记录原文实际出现的：
- 人物/称谓、地点、物件、组织、制度、章节/场景位置。
- 谁说了什么、谁相信什么、谁行动了、结果是什么。
- 明确事实、间接转述、人物回忆、人物猜测和叙述者说明的来源。
- 状态变化：目标、风险、关系、资源、能力、位置、所知与信念。
- 章节末尚未解决的具体问题。

### 第二遍：结构性解释（可以有不同意见）
利用第一遍的已验证对象构建：
- 行动的目标/阻力/代价/反馈链。
- 故事弧的起点、转折、阶段结算和跨卷继承。
- 主线、支线、人物弧、开放问题、伏笔/回收候选。
- 叙事顺序、倒叙/信息迟延、视角与读者期待。
- 作者的组织技法和可能的效果；需保留替代解释，不假装知道作者心理意图。

### 四层信息（可下钻，不相互覆盖）
L0：原文/章节/段落/引用位置。
L1：结构化观察（实体 mention、事件 mention、证词、状态变化）。
L2：小说内部叙事关系图（因果、时间、人物知识、故事弧、线索）。
L3：宏观分析（卷级结构、长期引擎、人物弧、读者体验、可迁移写法）。

### 三次校验
1. **机器校验**：JSON Schema、必需字段、source/split 归属、quote/hash/offset、一致性、越界章节。
2. **跨章反证**：是否存在后文推翻的说法、重复实体、假因果、同名误认或无法证实的回收。
3. **人工仲裁**：高影响合并、隐含因果、伏笔兑现、作者技法/主题解释和有争议的卷纲。

## 3. 分析粒度和“不能混为一谈”的对象

| 对象 | 真正含义 | 容易犯的错误 |
|---|---|---|
| Chapter | EPUB 正文阅读单元 | 一个 HTML 就是一个章节、一个章节只有一场戏 |
| Volume | 原书的卷/篇组织边界 | 卷界等于该阶段事件全部完结 |
| Arc | 围绕目标/案件/危机的情节单元，可跨卷 | 一卷必须有且只有一个 arc |
| CanonicalEvent | 故事世界中的同一件事 | 一处提及就新建一个事件 |
| EventMention | 某章节对事件的一次呈现/回忆/转述 | 把倒叙中的旧事件当成当章发生 |
| CharacterState | 某一时间/章节截面的状态 | 后文能力、身份、知识倒灌到前章 |
| Thread | 未解秘密、承诺、任务、伏笔候选的生命周期 | 同词重复出现就判为伏笔回收 |
| Plotline | 由共同目标/冲突/人物变化组织的持续路径 | 把人物出场列表当故事线 |
| Claim | 可核查事实或解释性结论 | 用户点击“接受”后就改成原文确定事实 |

注意：事件是否真实发生、某角色是否声称发生、读者是否获知、主角是否相信，是至少四个不同命题。

## 4. 一章到底拆什么：最小可靠章节卡

每章首先生成八块可审阅内容：

1. **位置**：work/source/split、volume、chapter、body hash、当前 reader cutoff。
2. **章节结果摘要**：不超过 3–5 个核心变更，明确“开始时—结束时”。
3. **事件节拍**：每个事件的参与者、行动/选择、前置条件、结果、事件 mention 和原文锚点。
4. **人物状态差分**：目标/所知/信念/资源/关系/风险前后如何变化；未变则空。
5. **读者信息变化**：新知道、暂时只能怀疑、被误导、重新理解了什么。
6. **开放问题**：新提出/继续/部分解答/完全解答，绑定 thread key。
7. **章节功能**：建立冲突、推进、揭示、人物塑造、过渡、节奏调节、阶段结算等，可多选且允许无强冲突。
8. **证据与审查**：引用验证状态、source kind、epistemic status、歧义及待人工问题。

强规则：
- 章节摘要不是事实来源；它只能引用事件与观察。
- 不允许以章节题目代替正文解读。
- 缺少事件可以留下描述性章节，不强迫每章都有逆转/爽点/钩子。
- 一个长段对话可能产生多条不同立场的 claim，不得压成全知叙述。
- 模型不能直接分配数据库 UUID；只返回局部 key，由服务端幂等解析。

## 5. 事件判定与因果判定

### 5.1 什么算独立事件
一个发生或被报告的可定位状态变化，通常可以回答：
- 谁作出了行动/决定，或谁受到影响？
- 原先是什么状态，后来怎样？
- 是现在发生、过去回忆、角色声称还是传闻？
- 结果能否成为后续行为的条件？

纯人物形容、世界设定说明、作者评论、气氛描写不默认作为“故事动作事件”。它们可作为 scene function / rule observation / interpretation 保存。

### 5.2 哪些边可以自动建议
- temporal_precedes：较明确的时间先后。
- motivates：某角色基于已知/相信的信息采取行动。
- causes：A 导致 B，需要机制和证据，不是“两个章节挨着”。
- enables/prevents：A 为 B 创造或阻断条件。
- reports/believes/knows/reveals：把信息来源和知识持有人明确化。
- foreshadows/payoff：只生成候选，人工需确认对应关系和文本支持。

### 5.3 三问反证法
A 是 B 的原因？必须回答：
1. 删除 A，B 是否仍可能同样发生？
2. 是否有第三个共同原因 C？
3. 原文有没有支持 A→B 的人物动机、制度规则、行动或叙述者因果说明？

缺乏依据时标 temporal/associated/inferred candidate，不硬造 causes。

## 6. 五本长期账本（超长网文的核心）

### 账本一：开放问题、秘密与伏笔
字段：thread_key、kind、original_question、introduced_anchor、appearances、interpretation_candidates、payoff_candidates、status_as_of_chapter、review_status。
状态候选：introduced、strengthened、misdirected、partly_answered、reinterpreted、resolved、open、unknown。
不把“第73章还没回收”当作全书失败；只说明在截止 73 章的快照里没有确认解决。

### 账本二：人物状态与关系
字段：entity_key、state_dimension、before/after、effective_story_time、first_revealed_chapter、informed_holder、event_key、evidence。
追踪身份、关系、能力、资源、伤势、目标、承诺、风险和信念；人物自己认定的秘密不等同于真实设定。

### 账本三：规则/资源/制度
字段：rule/resource、holder、acquire/use/transfer/loss、restriction、cost、rule_source、effective_scope、evidence。
在历史网文里“资源”可指官职、皇权、财政、户籍、奏请资格、亲缘关系和信用，不强制境界/等级。

### 账本四：事件因果/后果
字段：event、actor、preconditions、actions、consequences、causal_edges、counterevidence、dependencies。
用于回答“这一步为什么发生”“改变了什么”“删除一个事件会影响哪里”。

### 账本五：读者期待/阶段承诺
字段：promise、how_introduced、scope（章节/arc/卷/整书）、feedback_occurrences、settlement_status、cutoff。
不客观打“爽点分”；只解释哪些安排可能满足或改变读者预期。

这五本账本共享 L1/L2 数据：如果某事件被拒绝，下游账本必须显示受影响状态，不能各自持有不可校验的平行事实。

## 7. 从章到卷：归纳法而不是模板套入

建议先完成章节事实，再按 5–10 章窗口聚合提出候选 Arc，最终通读卷级开始/结尾进行复核。窗口是计算批次，不是预设小说每十章一定发生高潮。

每条 Arc 要回答：
- 初始处境/核心问题与触发条件是什么？
- 谁的目标占主导，是否还有并行目标？
- 关键人物作出了哪些选择？
- 什么能力、资源、信息、关系改变了可选行动？
- 出现了哪些转折或代价？
- 局部问题被解决了吗？怎么解决？哪些还没解决？
- 它怎样改变下一条 Arc 或下一卷的开始条件？
- 与全书潜在主线关系是明确事实还是解释？

卷纲必须包括“卷首状态 → 各 Arc 的里程碑 → 卷末状态 → 跨卷继承”。如果多个 Arc 并行/交叉，画为泳道或 DAG，而不是硬套一条时间线。

### 第一次实验的 Arc 候选（来自真实章节抽样，待全卷复核）
- 母妃处境与营救：第2章明确目标；第18章出现接母妃行动；第19–21章涉及回宫后的关系和后续处理。
- 落水疑云：第2章是模糊回忆；第13章有朱桢所说的齐王承认；第14章刘基声称目击。不同来源等级须分开。
- 刘伯温风险/药方事件：第13–14章铺设风险认知，第51/54/56/57/64/65章可观察到任务推进、药方差异、君臣交谈和代价；细节和因果待完整核查。
- 赴凤阳的下一阶段任务：第65章产生相关预期，第71–73章户贴/父皇任务/对外安排，第74章开始新卷。

这些是明确标记的**候选分段**，不是算法生成的正式主线；未来可能合并、拆分或发现隐藏交叉。

## 8. 真正的证据化：从章节到字符级

### 8.1 暂行 Pilot 规范化协议
- 按 OPF spine 读取章节 XHTML，而不是文件名排序。
- 保留章节标题为 metadata，不计入本次正文 offset。
- 去除 script/style 与 heading 后，按 p 元素抽取、去除首尾空白、用 LF 换行连接为 normalized_body。
- offset 为零基 Unicode 码点，end exclusive；quote_sha256 为该片段 UTF-8 的 SHA-256。
- 后续生产 normalizer 如果做标点转换、空白清理、段落合并等，必须增加版本号，不能复用当前 offsets。

### 8.2 锚点存储最低字段
source_version_id、split_version_id、chapter_id、chapter_body_hash、normalizer_version、start_char、end_char、quote_hash、epistemic_status、source_kind、verification_status。

### 8.3 引用校验
在锁定章节版本的 normalized_body 取子串，验证范围、文本和 quote hash 一致；若失败，保留 invalid，并由人工或重新对齐流程处理，不静默指向其他章节。

## 9. 第一卷工作量与审核方案

### Phase A：章界/证据底座
- 73 章完整索引、标题、spine 序、字符数和正文 SHA。
- 抽样 10 处来自第2、13、14、18、56、57、71、72、73章的实际短引用并计算 offset/hash。
- 通过目录/正文抽样验证第一卷开始/结束，不把章节索引当剧情标注。

### Phase B：逐章第一遍事实标注
- 每章至少确认主场景、人物 mention、重要事件、角色知识/状态差分、开放问题。
- 每条关键事件提供原文证据；无法定位的解释单独排队。
- 对第1–14章建立更细样本；中段与卷尾加密检查伏笔延续。
- 每章记录 reviewer、reviewed_at、修订版和疑点。

### Phase C：跨章归并
- 根据实体/事件语义、时间、信息来源和反例进行消歧。
- 形成候选 Arc、人物状态路径、规则/资源变化、线索账本。
- 把重要“角色声称”“推断”保留为独立对象。
- 特别检查第13/14章落水证词如何改变第2章的疑问状态。

### Phase D：卷级深度解剖
- 画并行 Arc + 事件因果 + 人物状态 + 信息揭示四种视图。
- 对第一卷的阶段性兑现和未解决目标分别标记。
- 对第73/74章执行跨卷承接审查。
- 通过事实链推导作者可能采用的结构手法，再反查证据。

### Phase E：方法验证
- 在固定人工作为参照的章节样本上比较“普通摘要→全书总结”与“结构化抽取→跨章归并→卷综合”。
- 固定章节、模型、prompt 版本、token 预算和切分。
- 比较事件召回/重复、实体误合并、因果误报、引用准确率、线索追踪正确率、截止章泄漏和人工审核时间。
- 人工复核有争议的“伏笔”“作者意图”“主线归属”，不追求不存在的单一正确解。

## 10. 从拆书到原创设计：反向迁移规则

**不复制剧情、文本或人物设定，只抽象问题设计机制。**

| 从原著抽到的结构 | 不应该怎么学 | 应转化成的设计问题 |
|---|---|---|
| 主角凭认知优势应对制度限制 | 照搬现代人穿越明宫 | 我的人物有什么真实而有限的认知优势？面对怎样的制度阻碍？ |
| 角色证词逐步改变谜团状态 | 直接照搬落水案 | 谁掌握信息？谁会误解或隐瞒？读者何时应得到什么证据？ |
| 某个营救目标跨多章推进 | 硬把前20章塞进一个“拯救任务”模板 | 目标建立后，每次行动增加什么条件、代价和关系变化？ |
| 原有场景问题转换为凤阳任务 | 新一卷换地图但完全重置人物 | 上一阶段的资源/关系/代价如何成为下一卷的新起点？ |
| 历史制度成为冲突条件 | 把历史常识直接当世界规则 | 哪条制度约束真正改变行动选项、成本与结果？ |

在原创工作台里生成的是可编辑的“问题清单 + 事件/状态依赖 + 候选结构”，不是原著复述或仿写引擎。

## 11. 质量门禁（先定义口径，阈值由 Pilot 决定）

硬门禁：
- source/split/chapter 版本错配数 = 0。
- 已标为 verified 的 quote 范围/hash 不匹配数 = 0。
- 截止章之后证据或派生摘要进入 reader_safe 视图的次数 = 0。
- 人工审核前，模型不应自动接受高影响实体合并或事实性因果。
- 原始 EPUB/章节全文不得被提交到公开设计仓库。

评价指标：
- KeyEvent recall/precision/duplicate rate。
- Entity resolution accuracy / false-merge rate。
- Causal edge precision 和无证据因果率。
- Thread introduction / payoff linkage precision。
- StateDelta consistency 与 character-knowledge leakage。
- 卷级 Arc 归属的人类一致性。
- 用户审核每一章和每一卷的成本。
- 相同模型/预算下，结构化方法相比逐章摘要基线的质量增益。

**拒绝伪指标**：模型自报 confidence、摘要字数、大纲章节数、爽点数量、强行的三幕结构完成度。

## 12. 需要验证的三条真正有价值的假设

H1（事实层）：结构化事件与知识状态标注，比只使用章节摘要更不容易丢失跨章节的事实和身份/知识边界。

H2（结构层）：开放线索账本结合事件因果和卷/Arc 归纳，比直接让模型从全书摘要猜伏笔更能追踪长距离线索，且误报更少。

H3（创作层）：使用从原著提取的状态/因果/阶段承接“设计检查问题”，比只生成一份长大纲更容易发现原创网文中的因果缺口、角色提前得知秘密和卷际目标断裂。

三条均是待实验假设，不能因为方法上合理就声称已获得验证。
