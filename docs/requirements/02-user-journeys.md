# 核心用户旅程与异常流程

状态：Draft

## 1. 旅程 A：导入小说并开始拆解

1. 用户进入项目，创建或选择作品。
2. 上传 TXT，前端显示上传状态和文件摘要。
3. 服务端校验大小、编码、内容类型和哈希。
4. 文件存入对象存储，创建 source document。
5. 预处理服务生成规范化 source version。
6. 章节识别产生 draft split version。
7. 用户预览章节列表和抽样正文。
8. 用户调整标题、边界、合并/拆分章节。
9. 用户确认切分，版本变为 confirmed。
10. 用户选择分析范围与分析项，创建 analysis run。
11. 前端展示阶段、完成数、失败数和预计剩余工作（有数据时才展示）。
12. 分析完成后进入结果审阅页。

异常：
- 同一作品重复上传相同文件：提示已有文档，可复用或创建显式副本，不重复执行昂贵解析。
- 章节识别失败：保留原文版本，允许手动创建章节或下载解析诊断。
- 文件只有目录/空文本：拒绝启动分析并指出具体原因。
- 上传成功但解析失败：源文件仍可访问，允许重试新解析版本。
- 用户离开页面：任务继续在后台运行，重新进入时恢复任务状态。

## 2. 旅程 B：查看章节细纲和证据

1. 用户打开某章节的细纲。
2. 页面展示章节摘要、事件节点、人物行动、冲突、信息变化、转折和章节功能。
3. 用户点击结论旁的证据标记。
4. 原文阅读器定位到对应章节及字符范围，高亮引用。
5. 验证器检查引用哈希和偏移；不匹配时不显示“已验证”状态。
6. 用户接受、编辑或拒绝结论。
7. 编辑后的结果形成新 artifact revision 或审核记录，原始模型输出保留。
8. 用户可以从人物、事件或故事线反向跳转到关联章节。

异常：
- 引用因版本不同而失效：显示原始版本和失效原因，不自动映射到新版本。
- 推断没有直接证据：显示“推断/猜测”，允许用户补充说明。
- 同一角色可能是两个人：进入实体消歧队列，保留候选项，不自动合并。

## 3. 旅程 C：审阅人物与故事线

1. 打开人物列表，按类型、状态、首次出现章节过滤。
2. 进入人物详情，查看别名、描述、目标、人物弧、关系、事件、故事线和证据。
3. 用户合并同一人物的别名或拆分错误合并。
4. 系统在事务中更新引用并写入审计记录。
5. 打开主线/支线时间轴，按章节排序查看节点。
6. 用户修改节点顺序、类型、解释或关联事件。
7. 系统重新校验引用和受影响摘要，必要时标记下游分析为 stale。

异常：
- 合并会产生自环或重复关系：先预览冲突，再由服务端执行去重与事务提交。
- 删除事件被其他线索引用：默认归档或拒绝删除，不做级联硬删除。
- 支线没有结尾：标记为“未识别到收束”，不能直接断言作者遗忘。

## 4. 旅程 D：重新分析与版本变化

1. 用户重新上传文件，或修改解析/规范化配置。
2. 系统创建新 source version 或 split version。
3. 历史分析仍关联旧版本，继续可查看。
4. 新版本下的产物标记为未生成或待重算；旧产物不伪装成最新结果。
5. 系统计算最小可重算范围。
6. 用户选择重算全部或指定章节。
7. 新 run 创建独立产物版本。
8. 用户比较旧版和新版，接受需要保留的人工修改。

## 5. 旅程 E：阅读导师

1. 用户选择阅读版本与当前章节。
2. 阅读器展示原文、阅读进度和笔记。
3. 用户请求导读或提出问题。
4. 系统优先检索当前章节、相关前文及用户授权的结构资产。
5. 回答展示证据、上下文范围和推断标签。
6. 用户将回答保存为笔记，或完成 AI 提出的复盘题。
7. 测验结果记录在阅读会话中，不反向改写原著分析。

## 6. 旅程 F：原创长篇创作

1. 创建 original work。
2. 设定故事定位和约束。
3. 建立 Canon、人物关系和世界规则。
4. 创建 planned outline，设计主线、支线和伏笔计划。
5. 生成章节细纲并人工确认。
6. 基于当前章节细纲、相关 Canon 和前文摘要生成正文草稿。
7. 检查矛盾并定位具体段落。
8. 用户接受/编辑正文，产生新 manuscript revision。
9. 更新已发生事实与 Canon 状态；不得把尚未写入正文的计划自动标记为已发生。

## 7. 全局交互原则

- 破坏性操作先预览影响，并提供取消。
- 长任务使用后台执行，不阻塞页面请求。
- 任务失败保留已完成阶段和可诊断错误。
- 每个 AI 结论都能查看来源和生成版本。
- 用户修改永远优先于未经确认的模型猜测。
