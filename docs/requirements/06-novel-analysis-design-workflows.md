# 小说拆解与原创设计：核心功能设计

状态：Draft · 核心能力优先级 P0

## 1. 产品目标

让用户能完成两件事：
1. 对一部已有小说做可核验、可编辑的深度拆解，形成可导航的故事模型。
2. 基于故事模型和作者意图设计原创长篇，逐级细化到卷、故事弧、章节和场景，并持续检查一致性。

产品不以“自动生成一份长摘要”为完成标准。核心交付物是结构化、版本化、带证据/理由的小说模型。

## 2. 两个主入口

### A. 拆解已有小说

入口：新建分析 → 选择作品类型/分析目标 → 导入文本 → 校对章节 → 选择分析深度 → 执行分层分析 → 审核人物/事件/故事线 → 查看全书结构。

### B. 设计原创小说

入口：新建创作 → 选择创作方式 → 填写创作简报 → 形成故事核心 → 设计人物与世界 → 建立事件因果骨架 → 规划故事线和结构 → 细化章节/场景 → 写作与一致性检查。

两个入口共享知识模型，但必须保留不同语义：
- 原著拆解中的事件是“文本表明/分析推断发生了什么”。
- 原创设计中的事件是“作者计划发生什么”，写进正文并确认后才成为“已写入的故事事实”。
- 不允许将计划大纲伪装成原文证据，也不允许把原著分析结论自动变成原创作品 Canon。

## 3. 反向拆解的功能流程

### A1. 作品识别与分析合同

用户选择/填写：
- 作品类型：独立长篇、系列小说、章回体、网络连载、群像/多视角、悬疑/推理、历史小说、其他。
- 分析目标：快速了解、完整拆解、人物研究、情节因果、主线支线、叙事技法、伏笔回收、写作借鉴。
- 分析深度：概览 / 标准 / 深度；不同深度控制抽取粒度和预算，不改变核心数据语义。
- 剧透范围：无剧透导读 / 读至指定章节 / 全书剧透分析。
- 可选结构模板：自由结构、三幕、五幕、英雄旅程、悬疑线索、章回/连载节奏、自定义。
- 输出必须标明分析范围、截止章节和未分析内容。

验收：用户可以明确选择全书剧透或局部阅读；模板不会改变原文事实，只影响展示和诊断问题。

### A2. 导入与章节校对

- 上传 TXT 优先；解析为不可变规范化文本。
- 自动提出章节标题和边界候选。
- 支持目录识别、回目识别、无标题文本的段落边界建议。
- 用户预览章节、合并/拆分、修改标题和顺序。
- 确认后生成不可变 split version；后续修改产生新版本。
- 每次分析固定绑定源版本和切分版本。

验收：章节边界可追溯；修订不破坏历史分析的定位；章节/场景不能混为同一概念。

### A3. 章节/场景细读

每章先建立局部分析，而非直接写全书总结：

- 章节摘要：本章发生了什么。
- 章节功能候选：引入、推进、阻碍、揭示、转折、汇合、兑现、过渡、氛围/人物塑造等，可多选。
- 场景切分候选：起止位置、时间/地点、参与人物、视角人物；允许整章为概述或内心叙述。
- 事件节拍：参与者、行动、目标/动机、前置条件、结果、处境变化。
- 人物状态变化：目标、知识、信念、关系、地位、资源、风险。
- 信息变化：读者知道了什么、角色知道了什么、哪些信息被隐藏/误导/重新解释。
- 叙述策略：故事时间、叙事顺序、叙述时长、重复/省略、视角/聚焦。
- 结尾状态：新问题、未解决冲突、悬念、承接动作；允许为空。
- 原文证据：所有重要事件和判断保留精确引用候选。

验收：不要求每章都必须有反转/高潮/悬念；每条重要结论能回到原文；模型不能为填满字段而编造事件。

### A4. 人物与实体地图

- 建立 canonical character/location/organization/object/concept。
- 保存每个原文 mention 的称呼、章节、位置、来源版本和消歧状态。
- 展示人物卡：目标、动机、价值观、能力、弱点、秘密、关系、资源、知识状态和变化轨迹。
- 展示关系的类型、方向、有效范围、证据和变化过程。
- 同名、化名、假身份、误认和转世等情况先作为候选；合并前显示冲突证据。
- 允许人物关系随时间变化，不将“当前关系”误作全书恒定关系。

验收：实体合并不丢失原文提及；能查看某一卷/章时人物知道什么、与谁是什么关系。

### A5. 事件与因果图

每个事件候选包含：
- 谁参与、谁采取行动、发生了什么。
- 目标/动机及其证据状态。
- 前置条件、触发事件、直接结果和延迟后果。
- 故事时间、叙事顺序、出现位置。
- 影响了哪些人物、故事线和未解决问题。
- 证据、反证、置信/审核状态。

关系至少区分：
- before/after：时间先后。
- causes/enables/prevents：因果、促成、阻止。
- motivates/decides/acts：动机、决定和行动。
- reveals/knows/believes/hides：信息揭示与人物知识。
- foreshadows/payoffs：铺垫与可能兑现。
- contrasts/echoes：呼应或对照。

时间先后不能自动推断为因果。对隐含因果要显示依据和不确定性。

验收：可按故事时间或叙事顺序切换查看；可追踪一件事的原因、后果及影响人物；因果边可人工修正。

### A6. 主线、支线与伏笔账本

- 从事件图提出故事线候选：主线、人物弧、政治/战争、情感、悬疑、家族、主题等。
- 每条线记录核心问题/目标、关键人物、起点、阶段转折、与其他线的交汇点、兑现/结束状态。
- 伏笔账本记录：首次出现、后续强化、误导/替代解释、候选回收、最终状态（已回收/部分回收/未解/无法判断）。
- 支线价值通过对人物、主题、因果、世界或主线的贡献解释，不能仅按篇幅判定。
- 允许一个事件属于多条故事线。

验收：每条故事线可回溯事件和章节；每条伏笔判断有证据或标记为推断；未解线索可筛选。

### A7. 全书结构与叙事技法

生成可编辑的多层结构：
- 作品 → 卷/部 → 故事弧 → 章节 → 场景 → 节拍。
- 叙事顺序与故事时间对照。
- 人物出场/视角分布、人物关系变化、事件密度和信息揭示节奏。
- 主线/支线交汇矩阵。
- 关键转折、高潮、低谷、结局和余波候选。
- 重复意象、主题母题、价值冲突及其在不同人物/事件中的变体。
- 可叠加结构模板进行诊断，但不自动把作品压成固定结构。

验收：结构层级可变；模板缺失不等于作品失败；宏观结论能下钻到章节和证据。

### A8. 审核与重算

- 结论状态：未审核、接受、拒绝、编辑；认知状态与审核状态分开。
- 人物合并/拆分、事件合并/拆分、因果边修订都保留操作记录。
- 用户修改章节切分后，仅将依赖旧 split version 的产物标记为历史/过期，不静默挪动证据。
- 单章重跑后，按依赖关系重算受影响的人物聚合、事件关系、故事线和全书结构。
- 显示覆盖率、引用有效率、未解决冲突和低置信关系。

## 3.1 工作台页面与交互结构

### 拆解工作台

- **作品总览**：作品信息、版本状态、分析覆盖率、关键发现、待审核事项、未解决线索。
- **章节阅读器**：左侧章节/卷导航，中间原文，右侧章节摘要、事件、人物提及、信息变化和证据；点击结论跳转到原文范围。
- **人物工作台**：人物卡、别名、关系、状态轨迹、出场章节、待消歧候选；合并/拆分前展示影响预览。
- **事件与时间线**：同一事件的不同 mention、叙事顺序/故事时间切换、因果前置与后果、信息揭示轨迹。
- **故事线工作台**：按主线/支线/人物弧分泳道；支持节点排序、交汇点、线索状态和来源证据。
- **伏笔/开放线索账本**：首次建立、强化、回收候选、未解状态、反证和人工结论。
- **结构浏览器**：作品—卷—故事弧—章节—场景—节拍；可叠加模板诊断，不强制模板。
- **审核与质量队列**：低置信实体、无效引用、因果冲突、重复事件、时间线矛盾和未解决解释。

### 创作工作台

- **创作简报与概念比较**：多个 premise/logline 版本并排比较，保存作者选择和未决问题。
- **人物与关系图**：目标、资源、限制、秘密、关系冲突和阶段状态。
- **世界/制度约束**：规则、来源、有效范围、代价、争议与虚构补白。
- **事件因果图**：计划事件、前置条件、选择、代价、后果、依赖项和结局反推。
- **故事线板**：主线与支线并行规划、交汇、线索建立与回收。
- **大纲树**：可变层级，支持移动节点、版本分支、冲突提示和影响分析。
- **一致性队列**：显示问题、证据/关联节点、影响范围和修复选项；由作者决定是否修改。

### 交互原则

- 图表是进入证据和编辑的入口，不是只读装饰。
- 选中任一图节点，应能查看详情、关联节点、来源、状态和变更历史。
- 用户编辑前显示受影响对象；批量修改必须有预览和撤销/版本回退路径。
- 复杂关系图提供过滤、搜索、分组和聚焦视图，避免一次绘制全书所有节点。
- 默认先展示少量关键结论，允许逐层展开细节；不能把全书所有信息同时塞进一个大屏。

## 4. 正向设计的功能流程

### B1. 创作简报

用户定义题材、目标读者、篇幅/连载方式、基调、核心问题、希望读者体验、不能违背的约束。允许信息不完整，并由 AI 提出问题，而不是强迫一次填满表单。

### B2. 故事核心

逐步形成：
- 一句话 premise/logline。
- 主角、目标、阻碍、stakes。
- 核心冲突和价值两难。
- 故事承诺/类型预期。
- 主题问题及可能的相反立场。
- 结局方向或结局候选。

允许保留多个方案并比较，用户选择前不自动冻结 Canon。

### B3. 人物、世界与制度

- 人物目标、动机、信念、矛盾、资源、限制、秘密、变化弧。
- 人物之间的利益、情感、权力、债务、忠诚和冲突关系。
- 世界规则、组织、地理、技术/超自然约束。
- 历史题材可记录史实来源、争议、虚构补白与时间约束。
- 设定需能产生行动和代价，避免仅建立百科全书式设定。

### B4. 因果骨架

从结局或核心问题反推，也可从人物行动向前发现：
- 初始状态与触发事件。
- 主角作出的关键选择。
- 选择带来的代价和不可逆后果。
- 对手/制度如何响应。
- 事件怎样升级、转向和收束。
- 哪些事件缺少原因、依赖尚未建立、人物动机不成立或只靠巧合推进。

### B5. 故事线和结构

- 建立主线与若干支线。
- 标记每条线的目标、冲突、变化、交汇和回收。
- 选择可选宏观模板：三幕/五幕、英雄旅程、悬疑、章回/连载、自定义。
- 将全书展开到卷/篇、故事弧、章节、场景和节拍。
- 每个节点至少说明叙事功能、人物目标、冲突/选择、结果和状态变化；不适用项允许为空。

### B6. 写作与一致性

- 生成章节草稿前，取当前章节细纲、相关 Canon、前文摘要、必要人物状态和未解决线索。
- 草稿与已确认 Canon 分开存储。
- 检查时间/地点、人物知识、人物关系、资源/规则、事件前置条件、伏笔回收和文风一致性。
- 用户改动设定或前文后，显示受影响章节和关系；不自动覆盖用户正文。

## 5. 首期功能优先级

### P0：必须先做
1. 导入、规范化、章节切分和校对。
2. 章节级事件/人物提及/信息变化的证据化抽取。
3. 人物消歧和事件因果候选。
4. 可编辑事件图、人物图、故事线与多层大纲。
5. 叙事顺序与故事时间分离。
6. 结论审核、引用验证、版本与局部重算。
7. 创作简报、故事核心、人物/事件/故事线/大纲的计划模式。

### P1：P0 质量达标后
- 伏笔账本、视角/叙述节奏、主题母题分析。
- 类型模板和结构诊断。
- 历史资料/世界规则/Canon 管理。
- 章节草稿生成和影响分析。

### P2：后续
- 自动整本长篇生成、多智能体自由创作、多人实时协作、公开发布和跨书知识库。

## 6. 核心验收指标

- 章节切分准确率及人工修正成本。
- 关键事件覆盖率与重复/遗漏率。
- 人物 mention 消歧准确率、错误合并率。
- 因果关系精确率（人工标注样本上评估）。
- 引用定位正确率和证据覆盖率。
- 伏笔/回收判断的人工一致性。
- 全书结构审核所需时间。
- 局部重跑是否只影响依赖项。
- 原创设计中的因果缺口、人物动机冲突、时间线冲突和未回收线索数量。

不以模型自报 confidence 作为质量指标；必须有人工标注的金标准样本和错误类型分析。

## 7. 明确不做

- 不把每章强制生成固定长度摘要作为核心能力。
- 不把每章等同于一个场景。
- 不强制所有小说符合三幕结构。
- 不将时间先后等同于因果。
- 不将语义相似等同于伏笔回收。
- 不将 AI 对主题/作者意图的推测当作事实。
- 不在未评审的情况下自动合并人物或覆盖 Canon。
- 不在一次 prompt 中输入整本长篇并要求一次性产出完整结构。
