# 现代网文拆解与创作设计：功能详设 V0.1

状态：Draft · 方向：超长连载与长期线索管理

## 0. 产品定位与导航

首页提供两条平行主路径：

- **拆解一部网文**：导入已获授权的文本 → 分卷分章 → 分层抽取 → 五类长期账本 → 整本结构透视 → 借鉴方法。
- **设计一部网文**：创作简报 → 长篇引擎 → 全书长期目标 → 卷/阶段规划 → 主线支线/人物/规则 → 章节细纲 → 创作诊断。

第一阶段优先交付拆解能力及其共享的数据/交互基座。原创设计先完成从创意到卷、故事弧、章节细纲的闭环，正文生成暂不作为核心验收目标。

网文覆盖玄幻、仙侠、悬疑、都市、历史、科幻、现实、游戏等；“现代网文”是媒介/文体概念，不限定现代背景。

## 1. 拆解工作台信息架构

- **W01 作品概览**：字数、卷数、章节数、作品状态（完结/连载中）、已分析截止章、故事核心、主要长期问题、分析覆盖率、质量提示。
- **W02 卷/阶段地图**：卷、阶段目标、阶段事件弧、主角处境变化、阶段结算、未完问题继承；卷与 arc 是两种视图，不强制一一对应。
- **W03 章节精读**：原文、事件节拍、角色/资源/信息变化、本章承接/兑现；点击任何卡片显示原文证据及认知状态。
- **W04 故事线泳道**：主线、人物线、势力线、谜团线、地域线；显示跨卷交汇和阶段延续。
- **W05 长期线索账本**：建立、强化、误导、部分兑现、最终回收、仍开放；可按章节/卷/人物/性质过滤。
- **W06 人物状态板**：时间截面下的能力、目标、资源、所知、所信、关系和伪装身份。
- **W07 规则/成长/资源板**：世界规则、权限/境界/财富/政治资源，升级或降级，使用代价与违反规则的候选冲突。
- **W08 事件因果图**：事件列表与有证据的 before/causes/enables/prevents/reveals 等关系；按故事时间/叙述顺序切换。
- **W09 连载节奏视图**：单章、短 arc、卷的目标建立、推进、困难、反馈、结算与新问题；仅作为结构诊断。
- **W10 审核台**：待消歧人物、疑似虚假伏笔、无证据因果、跨章时间冲突、旧版本引用、潜在剧透越界。

## 2. 基础结构单元

### Work 与连载快照
- 状态：ongoing / completed / hiatus / unknown。
- source_version + split_version 表示输入版本。
- publication_snapshot（规划）：可选的发布时间与更新范围，仅来自可信元数据。
- analysis_frontier：本轮允许模型读取的最大章节；任何产物保存 analyzed_through_chapter。
- 视图 cutoff_chapter：用户当前阅读进度/分析截止章，查询时禁止纳入未来证据。

### Volume 与 Arc
- volume 是出版/文本组织单元，可有卷名、章节范围。
- arc 是语义单元：单个目标、敌对力量、一个案件、一个副本或一次政治博弈，可跨卷。
- arc 属性：触发、目标、参与者、阻力、资源变化、关键选择、阶段结果、新开放问题、关联事件、证据。
- 一个事件可以贡献多个 arc；一个章节可以交织多条 arc。

### Chapter 与 Scene/Beat
- chapter 属于确认的 split_version。
- scene 是语义/时空场景候选，不自动等同章节。
- beat 是行动、决定、揭示、结果或状态变化的最小可用节拍。
- 摘要仅是便于阅读的视图，不能替代节拍数据。

## 3. 六个引擎的模块化拆解

| ID | 引擎 | 主要查询 | 核心功能 |
|---|---|---|---|
| ENG-01 | 目标 | 主角/组织追求什么，目标何时改变？ | 全书目标、卷目标、arc 任务、目标接力 |
| ENG-02 | 冲突 | 谁阻止谁，哪些规则限制行动？ | 对手/势力、制度、代价、选择链 |
| ENG-03 | 成长/资源 | 获得什么、失去什么，是否满足世界规则？ | 状态 delta、境界、资源、能力、损耗 |
| ENG-04 | 悬念/信息 | 什么信息被承诺、隐瞒、揭示？ | 线索生命周期、知识边界、伏笔回收 |
| ENG-05 | 世界展开 | 新设定何时出现，如何影响行动？ | 地图/势力/规则首次出现及使用 |
| ENG-06 | 人物关系 | 谁与谁的立场和关系变了？ | 人物关系时间轴、承诺/债务/信任变化 |

对于没有战力/等级体系的题材，ENG-03 可以映射为技能、信息、财产、政治资本、法律地位等非数值资源。

## 4. 五种长期账本：具体操作

### LEDGER-01 开放线索/伏笔
- 用户看到一个线索的“首次证据 → 后续提及 → 解释/误导 → 回收候选 → 审核状态”时间轴。
- 线索类型：秘密、谜团、预言、人物身份、承诺、未完成任务、物品来源、世界规则异常、潜在伏笔。
- 状态：open / strengthened / partially_resolved / resolved / reinterpreted / abandoned_candidate / unknown。
- “未回收”只说明截止当前分析范围仍无确认兑现；对连载中作品不视为缺陷。
- 回收必须关联此前建立点与后续结果，并对“为什么它们是同一线索”提供证据；语义相似只是候选。

### LEDGER-02 人物状态
- 查看截至某章角色的目标、能力、伤势/风险、资源、身份、所属组织、人与人关系、知识与信念。
- 记录状态变化 delta：before、after、event、evidence、effective_story_time、first_revealed_chapter。
- 角色知识与读者知识分开，避免用后文答案污染角色当时的决策分析。
- 身份误认、化名、伪装及同名留在候选消歧状态，不能静默合并。

### LEDGER-03 资源与规则
- 资源：等级/境界、法宝、金钱、人脉、情报、组织权限、名望、地盘、政治支持等。
- 变化类型：获得、消耗、转移、损毁、借用、升级、降级、未知。
- 规则：谁知晓/谁能使用、使用代价、限制、例外、是否已被证实。
- 系统可提示“疑似战力崩坏/规则矛盾”，但先展示规则与事件的原文依据。

### LEDGER-04 事件因果
- 事件节点：人物、选择、行动、前提、结果、后续影响。
- 边类型：precedes/causes/enables/prevents/motivates/reveals/echoes。
- 模型的隐含因果必须标注 inferred 并列出反例/替代解释。
- 可从任一重大事件回看“导致这一步的三层前置条件”。

### LEDGER-05 读者期待与阶段承诺
- 期待来源：叙述承诺、人物承诺、悬念、对手、成长路径、悬而未决的价值问题。
- 轨迹：建立、等待、局部反馈、转向、兑现、仍开放。
- 提供章节钩子分析，但绝不要求每章都有钩子或高潮。
- “爽点”标注为读者体验候选，可描述情绪来源（逆转、突破、关系变化、揭示、复仇、胜利等），不生成客观文学质量分数。

## 5. 拆书任务流水线

1. 用户选择 work、source/split version、截止章、分析深度和关注引擎。
2. 固定 analysis manifest；启用严格 cutoff_chapter 权限。
3. 按章节分析 mention、beat、事件、人物/资源 delta、信息揭示与引用。
4. 局部跨章节合并实体/事件，并对歧义保留候选。
5. 跨章抽取 arc、目标继承、因果图、线索账本。
6. 按卷综合：阶段目标 → 阻力 → 关键选择 → 结算 → 遗留 → 下一卷承接。
7. 全书综合：六引擎及五账本、跨卷因果、人物弧、长期承诺与终局。
8. 对所有关键结论验证原文证据、章节范围和认知状态。
9. 用户审核有争议的合并、因果边、伏笔/回收候选。
10. 用户修改后局部重算受影响对象和上游摘要，不全量重分析。

### 核心规则
- **源文本版本不可变**；正文和切分修订创建新版本。
- **分析不能越过截止章**；即使数据库已有整本资料。
- **不同视图同一来源**；人物、线索、因果和故事线不能各自持有互不一致的事实。
- **没有依据就保留未知**；模型不能为了填完整大纲猜测未写的剧情。
- **动态连载允许无终局**；对未完作品提供“当前最合理路径/候选”，不声称已知结局。

## 6. 原创网文设计工作台

### DESIGN-01 连载创作合同
题材、目标读者、预计篇幅、更新节奏偏好、视角、基调、作品状态、创作自由度。连载运营指标应作为可选目标，不压过故事质量。

### DESIGN-02 长篇故事引擎
- 全书主问题/长期目标。
- 主要冲突及其扩大机制。
- 主角的可持续成长动力（不一定是战力）。
- 长期谜团/知识差/身份秘密。
- 世界展开的规则与边界。
- 人物关系长期变化。
系统提出“写到中后期之后，还能自然产生什么新问题？”等可验证的设计问题。

### DESIGN-03 分卷引擎
每卷卡片包含：阶段目标、进入条件、对手/环境、关键事件、增长与代价、高潮/结算候选、跨卷线索、卷末状态。卷不是简单按章节数切块；允许无明确阶段高潮。

### DESIGN-04 故事弧与任务单元
支持并行的案件、副本、政治博弈、组织目标、人物关系等 arc，显示其跨章节/跨卷的生命周期。每个 arc 可以借用“目标—行动—阻力—选择—反馈—结算”检查，但不是强制场景公式。

### DESIGN-05 人物/能力/资源/规则
人物状态随事件推进；展示截止每章的能力/资源/知识，不允许角色提前使用尚未获得的能力和秘密。历史/现实题材复用“制度、组织、地理、资源”而不是强行生成境界。

### DESIGN-06 伏笔与信息调度
作者可规划线索首次出现、强化、误导、部分回收、最终揭示或刻意开放；提前生成“卷内未解决”和“跨卷待回收”列表，按其依赖和风险排序，不以天数/章数一刀切判断风险。

### DESIGN-07 章节与节拍
从卷/arc 展开章节：承接的状态、该章推动的目标/线索、行动或揭示、资源/人物/知识变化、章末状态。生成细纲前显示相关 Canon 与未解决任务，正文生成仍后置。

### DESIGN-08 一致性诊断
- 角色提前知道未来秘密。
- 人物/组织关系无铺垫反转。
- 资源没有获得就被消耗。
- 世界规则例外缺少解释。
- 伏笔回收与建立时内容冲突。
- 前置事件发生在后果之后。
- 卷之间目标断档、长期主问题被遗忘。
- 新副本/新地图只是旧任务换皮（候选）。
每个发现必须展示具体受影响节点、证据/规则和多个修复选择，不能自动判作品失败。

## 7. 典型操作场景

### 场景 A：一本书已更新到第 800 章，用户只读到 280 章
页面设 cutoff=280；所有人物身份、结局、后续伏笔结果和知识变化只展示截至 280 章的已知内容。可对同一个线索保存“截止280章仍开放”状态；若之后读到 500 章再进入新版视图，才能显示新发现。

### 场景 B：一条线索从第 12 章到第 670 章兑现
线索账本显示首次建立、三次后续强化、一次误导、卷间间隔、首次部分解释及最终回收；所有关联位置可以一键定位原文。原文没有明确呼应时仅作为 inferred candidate。

### 场景 C：作者调整了第三卷主角获得关键能力的时间
影响分析沿着该能力的 acquisition → use → consequences 依赖关系找出所有“提前使用能力”的章节与剧情。提供修复建议，不直接重写全部正文。

## 8. 验收指标（基线阶段由人工标注定义阈值）

- 章节/分卷识别与边界修正次数。
- 核心事件 recall、重复事件率。
- 角色误合并率、人物状态 delta 准确率。
- 线索首次出现/兑现的定位准确率与误报率。
- 卷/arc 归属人工一致性。
- 时间/因果关系人工精确率。
- cutoff 越界泄漏率（目标为 0）。
- 历史版本引用验证率。
- 人工审核一卷的时间与修改次数。
- 对原创设计的“提前使用能力/知识”等违规检出率与误报率。

所有比率在固定的、有授权的人工标注基准集上测量，不使用模型自评替代外部测试。
