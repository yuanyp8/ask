# 小说拆解与设计方法调研

状态：Draft · 研究基线 v1

## 1. 研究问题

ASK 不是“把小说总结得更短”的工具，而是要回答：

1. 文本里明确写了什么？
2. 故事世界中发生了什么，事件之间如何关联？
3. 作者按照什么顺序、视角和节奏把信息交给读者？
4. 人物如何在目标、选择、关系、知识和处境变化中推动故事？
5. 多条故事线如何开始、发展、交汇、兑现或保持未解？
6. 创作者怎样从一个创意建立一套可持续扩展、可验证、可修改的长篇设计？

研究结论必须转化为可操作的产品流程、数据语义、校验规则和用户决策点；不能只罗列文学理论名词。

## 2. 方法对比

| 方法/理论 | 主要解决的问题 | 对 ASK 的价值 | 不能直接照搬的部分 |
|---|---|---|---|
| 叙事学：fabula / sjuzhet | 故事发生顺序与文本叙述顺序的区别；叙述时长、频率、视角 | 是反向拆解的基础：分别保存故事时间、叙事顺序、信息揭示顺序 | 不能只用时间线替代叙事分析；不同学派术语存在差异 |
| 事件与因果图 | 谁采取了什么行动，导致或阻止了什么，信息如何传播 | 把摘要升级为可追踪的事件关系图，支持主线、人物弧和伏笔分析 | NLP 对跨段指代、隐含因果、开放世界因果仍不可靠，需保留候选与证据 |
| Story Grid 场景诊断 | 触发事件、升级、危机选择、高潮行动、结果；场景价值变化 | 诊断局部场景是否真正改变处境、关系、知识或风险 | 不应要求每章/每场景都有强冲突；氛围、铺垫、回忆和内心活动也可能有功能 |
| Save the Cat! 15 beats | 常见类型故事的宏观节拍与人物转变 | 可作为一种可选结构模板，帮助检查节奏和类型承诺 | 电影剧本传统不等于所有小说的普遍定律；不能强制百分比、三幕或固定转折点 |
| Snowflake Method | 从一句话概念逐步扩展到梗概、人物、场景和初稿 | 适合正向设计的层级展开；每层产物可评审，再继续细化 | 不应假设线性流程；创作发现可能要求回到前面重构 |
| 中国章回体与网络连载研究 | 分卷、章回、故事单元、章末悬念、长篇连载节奏 | 对百万字长篇的卷—弧—章管理、悬念账本和周期性兑现尤其重要 | “十章一单元”“三章小高潮”等属于观察到的创作惯例，不是普适定律 |
| 数字人文/文本量化叙事研究 | 从大量文本中识别叙事曲线、节奏和语言特征 | 可做宏观节奏、人物出场密度、视角切换和情绪变化的辅助指标 | 量化曲线不能单独解释文学价值；结构符合度不等于作品质量 |

### 2.1 叙事学是“拆书”的底层坐标系

哈佛大学的小说阅读教学明确区分 fabula（故事事件）与 sjuzhet（文本如何呈现事件），并讨论顺序、时长、频率和聚焦/视角。由此推导出一个关键的数据要求：

- **故事世界时间**：事件在虚构世界中何时发生。
- **文本叙事顺序**：读者在什么章节、场景、段落中接触到它。
- **信息揭示顺序**：读者、叙述者和角色分别在何时知道什么。
- **因果关系**：事件是否导致、促成、阻止或改变另一个事件。

这四种关系不能压成一个 time/order 字段。倒叙、插叙、隐瞒、误认、多视角和不可靠叙述都会因此被误读。

参考：[Harvard — How to Read a Novel](https://claybaugh.scholars.harvard.edu/pages/how-read-novel-0)

### 2.2 事件抽取只是起点，连接关系才是结构

叙事抽取研究通常涉及事件识别、参与者识别、时间与空间信息，以及事件间的指代、时间、因果关系。仅仅抽取人物和事件，不足以还原情节。计算叙事研究也指出，显式建模事件因果能够改善故事理解相关任务，但开放世界的隐含因果仍是困难问题。

ASK 应采用“候选抽取 → 关系推断 → 证据校验 → 人工审核 → 全局综合”，而不是让一次 LLM 调用直接产出全书定论。

参考：
- [A Survey on Narrative Extraction from Textual Data](https://link.springer.com/article/10.1007/s10462-022-10338-7)
- [Event Causality Is Key to Computational Story Understanding — NAACL 2024](https://aclanthology.org/2024.naacl-long.191/)
- [Plot Extraction and the Visualization of Narrative Flow — Cambridge University Press](https://www.cambridge.org/core/journals/natural-language-engineering/article/plot-extraction-and-the-visualization-of-narrative-flow/445A7A36F339A280AA1EA5A6612373A0)

### 2.3 场景方法应当是诊断镜头，而非全书强制模板

Story Grid 的五个关键环节为：触发事件、渐进复杂化/转折、危机、高潮行动、结果。它适合检查一个场景中人物面对什么选择、做了什么、局面如何变化。产品应允许场景标注“铺垫、揭示、过渡、回忆、氛围、关系变化”等功能；若不适用某个环节，应允许为空，而不是诱导模型编造冲突。

参考：
- [Story Grid — Five Commandments of Storytelling](https://storygrid.com/articles/five-commandments-of-storytelling)
- [Story Grid — How to Write Scenes](https://storygrid.com/articles/scenes)

### 2.4 宏观结构要模板化，但不能教条化

Save the Cat! 的 15 beats 对常见类型小说的节奏设计有帮助；Snowflake Method 通过逐级展开降低长篇规划的复杂度；两者解决的任务并不相同。产品应把它们实现为“可选模板/诊断规则”，而非底层数据模型的硬约束。

参考：
- [Save the Cat! — How to Write a Novel](https://savethecat.com/how-to-write-a-novel)
- [Randy Ingermanson — Snowflake Method interview](https://www.creative-writing-now.com/the-snowflake-method.html)

### 2.5 中国长篇/网络连载需要额外维度

中国作家网关于章回体向网络文学转化的研究讨论了分卷、回目、章末悬念与连载单元；关于网络小说长度的研究则强调超长篇、人物与事件容量、场景铺排和连载媒介的影响。这意味着 ASK 需要管理“卷/篇/故事弧/章节/场景”多层结构，以及跨章节的悬念、线索和兑现关系。

但不能把某种章法固化为所有作品的规则。古典章回小说、现代文学长篇、百万字连载、群像历史小说和悬疑小说的结构重心可能完全不同。

参考：
- [中国作家网 — 网络文学对古典小说叙事的转化](https://www.chinawriter.com.cn/n1/2023/0707/c404027-40030147.html)
- [中国作家网 — 中国网络小说的“长度”问题研究](https://www.chinawriter.com.cn/GB/n1/2022/0826/c404027-32512222.html)
- [中国作家网 — 长篇小说的结构问题](https://image.chinawriter.com.cn/n1/2021/0407/c404030-32071765.html)

## 3. 对产品设计的结论

### 原则 A：一个底座，两条工作流

- 反向拆解：从文本证据出发，恢复故事模型并解释作者如何叙述。
- 正向设计：从作者意图出发，创建计划事件、人物变化、故事线与大纲，再检查因果和一致性。

两条工作流共享人物、事件、关系、故事线、结构树、时间和版本能力，但不能混淆来源和状态。

### 原则 B：事实、推断、假设分开

每条结论必须区分：
- explicit：原文明确陈述或直接可验证。
- inferred：基于文本证据的解释。
- speculative：存在多个合理解释，或证据不足。

“作者想表达什么”“某条支线是否多余”“一个细节是不是伏笔”通常是解释性结论，必须展示依据与替代解释，不得伪装成确定事实。

### 原则 C：章节不是场景，摘要不是情节图

章节是出版/文本组织单元；一个章节可以包含多个场景，也可以主要由回忆、概述或内心独白组成。摘要保留“讲了什么”，但事件图还要保留参与者、行动、前置条件、结果、因果、信息变化和原文位置。

### 原则 D：多尺度结构可变

默认提供 work → volume/part → story arc → chapter → scene → beat 的可变层级，但允许某些层级缺失、重复或使用用户自定义名称。三幕、英雄旅程、章回节奏、悬疑结构等均作为可叠加分析视角。

### 原则 E：LLM 负责提出候选，系统负责验证和组织

模型可以提出事件、别名、因果边、伏笔候选和主题解释；服务端校验引用、版本、ID、关系约束与 schema；用户审核歧义和高影响结论。模型不得直接把自己推断的 UUID 或事实写进正式领域数据。

### 原则 F：长篇分析必须分层、可恢复、可追溯

按章节/场景抽取局部信息，跨章节消歧与聚合，再生成全书综合；每层产物保留源版本、证据和依赖。全书摘要不能成为唯一记忆，也不能替代底层事件/人物/线索索引。

## 4. 调研结论的边界

本轮是面向产品设计的桌面调研，不是对所有方法进行系统综述，也未对具体小说做完整标注实验。下一步需要选取不同结构类型的代表作品，建立人工标注样本，验证事件、因果、视角、伏笔和结构结论的质量，再决定哪些规则进入自动校验。
