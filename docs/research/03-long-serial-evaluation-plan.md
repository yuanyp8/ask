# 现代网文方法验证计划与黄金标注规范 V0.1

状态：Draft · 目的：在编码之前验证长篇拆解的方法与优先级

## 1. 验证目标

不是比较“AI 生成的大纲有多漂亮”，而是判断 ASK 是否可靠识别长期叙事的实体、事件、阶段任务、状态变化和线索生命周期。尤其验证：
- 超长篇中的**跨卷线索**能否正确连接。
- 截止第 N 章的分析是否完全避免后文泄漏。
- 任务/升级/博弈与人物关系、社会结构类叙事能否用同一底座表达。
- 事件因果、人物消歧和资源规则能否被人工审核而不是只能读摘要。

## 2. 代表性样本（候选，须先取得合法文本访问权）

| 候选 | 代表机制 | 重点测试 |
|---|---|---|
| 《诡秘之主》 | 诡秘悬疑、序列/能力规则、伪装身份、跨卷真相 | 伏笔账本、信息揭示、角色不同身份、规则代价、卷间继承 |
| 《凡人修仙传》 | 长期修炼、资源积累、阶段目标、世界拓展 | 资源/境界变化、阶段结算、主角行动依赖、人物关系跨度 |
| 《大奉打更人》 | 案件、线索、权力/势力关系与长期秘密 | 案件弧、因果与线索层次、人物认知边界 |
| 《亏成首富从游戏开始》 | 都市/系统规则、反预期、任务与反馈 | 规则约束、角色所知与读者所知、反馈循环 |
| 另选一部连载中作品 | 截止章节随更新变化、尚未回收的线索 | 发布/分析快照、增量更新、未知终局、避免未来剧透 |

样本选择是**覆盖不同机制**而不是给小说排名。具体版本、可用正文、分卷边界、章节编号和版权授权均需记录。禁止未经授权抓取全文来构建基准集。可使用合法提供/自有文本，或先做短文本人工样例。

## 3. 分层抽样

### T0：微型功能样本
人工编写或获得授权的 3–5 章文本；覆盖假身份、角色知识差、资源消耗、未回收线索、后文回收、因果歧义。用于检验数据结构、约束和 UI 核心交互。

### T1：章节簇（每本）
挑选开篇连续章、一次阶段中段、一次阶段结算，分别覆盖：引入→推进→部分兑现、新地图/新规则、角色关系变化。

### T2：完整卷/阶段
选择一个完整卷或较完整的 arc；观察目标—行动—阻力—结果—新问题是否可以闭环。记录无法套用任务循环的反例。

### T3：跨卷长距离线索
至少挑选若干经过不同卷/阶段、相隔数十至数百章的线索，对同一物品、身份、承诺、谜团或世界规则从首次出现至回收/未知做追踪。

### T4：不同截止章快照
同一部作品在 chapter=100、300、latest-known 三个 cutoffs 下分析；确保第100章的视图不包含300章才知道的真相，并正确保留“当时合理但后文推翻”的解释。

## 4. 人工标注单位

- **EntityMention**：原文提及、canonical candidate、歧义/同名/化名状态。
- **Event**：最小叙事事件、参与者、行动、前置条件、结果。
- **StateDelta**：人物/资源/关系/知识在事件前后的变化及证据。
- **EventRelation**：before、causes、enables、prevents、reveals、echoes；因果须独立给依据。
- **Arc**：阶段目标、起止位置、关键事件、局部结算、跨卷延续。
- **Thread**：首次出现、重复、强化、部分回收、重解释、完全回收、截至 cutoff 未解决。
- **NarrativeObservation**：视角、信息揭示、叙事与故事时间差异。
- **Evidence**：source/split/chapter、引用起止、引用文本/hash、认知状态。

原文明确陈述的事实与分析者解释分开。每个标注必须带分析截止章节；未有证据的关系保持候选状态。

## 5. 标注指南

1. 两人独立标注（有条件时），争议由第三人裁定并记录理由。
2. 先标文本中可定位的事实/提及，再标因果和伏笔等解释。
3. 可多标签、多故事线；不强求单一正确故事结构。
4. “没有确认回收”不等于“作者忘了”；连载中的未知应标为 open/unknown。
5. 按读者当时已获知的内容标注 cutoff 视图，不使用后文补全之前的确知事实。
6. 原文证据不足时不猜测，记录 unsupported/ambiguous。
7. 保存标注规范版本与仲裁记录，保证跨模型比较可复验。

## 6. 主要评价指标

| 指标 | 计算/判断口径 | 特别注意 |
|---|---|---|
| Event precision/recall | 以人工事件标签为基准做同义匹配和漏检核查 | 一事件被拆成多个节点时要另计重复率 |
| Entity merge error | 错误合并 canonical entity 数 / 人工校对的实体合并决策数 | 假身份与同名容易产生严重错误 |
| Evidence validity | 可验证引用数 / 要求提供引用的结论数 | offset、quote、版本同时一致 |
| Thread continuity | 正确跨章节/跨卷连接的线索数 / 人工标注目标线索数 | 单一关键词重复不构成同一线索 |
| Payoff precision | 被判断为回收且人工认可的数量 / 所有回收预测数量 | 不把暗示或呼应都硬判为兑现 |
| Temporal/causal precision | 正确关系边 / 被人工审核的关系边 | 时间先后不得自动视为因果 |
| Reader cutoff leakage | 含未来章节信息的视图数 / cutoff 视图总数 | 目标为零；作为硬门禁 |
| Arc coherence | 人工评审阶段目标/结算/承接是否一致 | 需记录评审者意见而非模型自评 |
| Review workload | 完成人工确认一卷事件/人物/线索所需时间 | 同时记录误报造成的操作成本 |
| Creative diagnostic accuracy | 真实冲突检出与误报 | 用人工设计的有缺陷/无缺陷大纲验证 |

首轮先测基线，不在无样本时编造目标精度。基线稳定后才能设门槛。

## 7. 模型与方法对照实验

同一批标注样本上比较：
- 直接每章自由摘要 → 全书总结（baseline）。
- 每章结构化提取 → 跨章节归并 → 全书综合。
- 结构化提取 + 源证据检索 + 人工审核。
- 可选对照：卷/arc 中间综合是否减少跨卷漏检。

固定输入章节、cutoff、token 预算、prompt/schema 版本、模型路由与评审规则。记录费用、延迟、质量，而非只比较“看起来全面”。

## 8. 验证完成的决策门槛

- 必须解决后文泄漏和跨版本错位的系统性问题。
- 对核心事件、人物状态、线索连续性有可量化基线。
- 能解释假因果、假伏笔、错误实体合并的主要原因。
- 一卷的人工审核成本可接受。
- 能证明使用结构化故事模型，对长篇“跨卷关系追踪”的帮助优于简单逐章摘要。

只有这些问题得到验证，才把六引擎/五账本的高成本分析全部纳入自动流水线。
