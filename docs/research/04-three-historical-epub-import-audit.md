## 来源与范围

由用户直接上传的三份 EPUB；本报告只记录**文件结构、章节级分析假设及少量转述**，不将原著全文、长段摘录、封面或电子书字节提交到仓库。版权作品仅在用户授权使用范围内处理。

## 1. 导入解析策略

### 1.1 不得使用物理文件数量推断章节数

- OPF manifest 负责定位资源，OPF spine 负责正文线性顺序。
- NCX/nav TOC 负责卷/篇/章节导航候选；链接需解析相对路径和 fragment。
- 正文 heading 负责找真正的章节边界；一个资源内允许多个 chapter。
- 二者不一致时保留 discrepancy 供人工确认，不能静默删掉无法对齐的章节。

### 1.2 卷/篇与章节编号分开

- volume_no / volume_label：由目录或正文标识决定。
- chapter_display_label：保留原著“第一章”“第001章”等原样。
- chapter_sequence：服务端按 spine + chunk 生成的唯一阅读顺序。
- chapter_number_local：可为空、可重置、可重复；例如《官居一品》的“923（上）/923（下）”。
- chapter_suffix：上/中/下等保留在标题及可选解析字段。
- position/reading_order 与 volume/arc 是不同维度：Arc 可以跨卷。

### 1.3 非正文章节必须分类

front_matter（封面、内容简介、制作说明）、body_chapter、volume_heading、finale、afterword、extra/side_story、toc_duplicate、unknown。

- 《父可敌国》：最终章、完本之后说明、番外壹～肆不能作为无效 HTML 丢弃。
- 《官居一品》：最后一个 HTML 自带 Table of Contents，切章时不应二次计入。
- 《小阁老》：后记与篇标题都应保留并分类，不计入“正文事件提取”默认范围。

### 1.4 元数据校验

作者、书名以 EPUB metadata 为第一候选，同时结合封面/版权信息与文件名人工确认。本批《父可敌国》OPF creator 缺失；不能仅凭文件名强制覆盖作品事实。实际导入需要显示 metadata confidence 和人工修正入口。

### 1.5 保留来源定位

每个章节保存：source_document_id、source_version_id、split_version_id、source resource href、spine index、fragment/节点候选、规范化全文 offset、章节局部 offset、内容 hash。标题/正文的划分策略必须版本化；旧版本的 evidence anchor 不重定位覆盖。

## 2.1 第一卷/篇切换的具体对齐观测

- **《官居一品》**：第一卷末尾正文标题到第078章《卖与立（下）》，第二卷由第079章《祝福（上）》开启；这次**卷切换发生在同一个 HTML 物理文件内部**（spine index 2，零基）。因此“同一个 HTML = 一个卷”同样错误。
- **《小阁老》**：第一篇第七十二章《老哥哥这是怎么了？》后是独立的第二篇《风起钟山》目录节点，然后第七十三章《特大喜讯》。篇标题占据 EPUB spine 中单独的内容入口。
- **《父可敌国》**：第一卷第七十三章《好男儿志在四方》后，第二卷《中都风云》的标题入口在一个几乎不含正文的 XHTML 中；第七十四章《临淮知县韩宜可》才是第二卷正文。依赖“页面文字首行为卷标题”可能漏掉卷界，需要组合 NCX/TOC 与 spine。

由此必须支持至少三种卷界情况：**同一 HTML 内切换、独立篇标题 HTML、TOC 主导且内容近乎空的卷界 HTML**。

## 4. 这些样本会改变什么架构决策

- 章节主键不能由 chapter_number 推导；必须是独立稳定 ID + split_version + reading_order。
- HTML resource 不等于 chapter；卷/篇更不能等于 HTML resource。
- 分卷信息不宜只存在大纲 tree 中，需要可查询的作品组织层级（哪怕初期只是标注 Artifact）。
- 作品的“最终章/番外/后记”会影响“已完结、已回收”的评价范围。
- 同作者作品之间可以做写作手法对照，但**不能**自动把人物、世界、事件认定为同一连续宇宙。
- 这些现代历史网文的制度、历史、家族和政治资源值得用统一的“资源/规则/关系”模型表示，不能只针对玄幻网文建立等级表。
